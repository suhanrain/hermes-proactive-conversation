# Multi-language (i18n)

[**English**](i18n.en.md) | [简体中文](i18n.md)

Some rules are **language-dependent**: regexes that block pressuring/blaming wording, the word list that detects a bare acknowledgement, the minimum content length, and the default prompt wording. These are organised into **`LocaleProfile` data files** (under `proactive/locales/`); **`proactive_locale`** selects which profile to use, and leaving it unset keeps only language-neutral structural filtering.

Where content filtering sits in the flow, why it exists, and what each rule blocks → see **[core architecture and flow](architecture.en.md)**.

## Available profiles

| Value | Behaviour |
|---|---|
| **unset / `null` (default)** | **Neutral**: no language regexes / acknowledgement words / minimum length; only **structural filtering** (machine text markers + compaction structure positions) → never over-filters. |
| `zh-Hans` | Simplified Chinese profile: a set of pressuring/blaming/dependency regexes, Chinese acknowledgement words, `min_chars=6`, Chinese default prompts. |
| `en` | English profile (**starter skeleton, extensible**): common English regexes, English acknowledgement words, `min_words≥2`, English default prompts. |
| `auto` | Read the host locale: `zh*`→`zh-Hans`, `en*`→`en`; if unavailable or no profile → fall back to `en` with a `WARNING` (still counts as "active"). |
| any other value | Invalid → `WARNING` + **neutral** (fail-safe: no crash, no over-filtering). |

- **`machine_markers` are always global**: `[CONTEXT COMPACTION`, `Gateway message origin (`, `[Cron delivery: ` etc. are fixed English wrappers injected by the host, independent of the user's language, and are blocked in **every** mode.
- Only `proactive_locale` decides whether language filtering is active: unset = no language filtering; set = active.
- `/proactive-check` shows the current `proactive_locale` (source / active or not).

## Adding a language profile

1. Add a `LocaleProfile` in `proactive/locales/__init__.py` (see `ZH_HANS` / `EN`):
   - `expression_patterns`: a list of `(area:slug, regex)`; ids use `area:slug` (e.g. `pressure:last-chance`), and each new rule should come with a test;
   - `acknowledgement_words`: whole-sentence bare acknowledgements;
   - length unit: CJK uses `length_unit="chars"` + `min_chars`; space-delimited languages use `length_unit="words"` + `min_words`;
   - `wording`: a `Wording` (default text for soft/forced rounds; the tool-availability clause is appended by code and is not part of the profile).
2. Register it in `PROFILES` and add optional aliases in `_ALIASES`.
3. Add the code to `proactive_locale.enum` in `plugin.yaml`.

`en` is explicitly a **starter skeleton**: its regexes and acknowledgement words cover common shapes only; extensions are welcome (keep id shapes consistent and add tests).
