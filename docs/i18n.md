# 多语言（i18n）

[English](i18n.en.md) | **简体中文**

插件里有一部分规则**与语言相关**：拦截施压/指责措辞的正则、判断「纯应答」的词表、内容长度下限、以及默认提示词文案。这些规则按语言组织成 **`LocaleProfile` 数据档案**（位于 `proactive/locales/`）；**`proactive_locale`** 决定启用哪一档，不设置则只保留与语言无关的结构过滤。

内容过滤在整个流程里处在哪一环、为什么要过滤这些、各自挡什么 → 见 **[核心架构与流程](architecture.md)**。

## 有哪些档位

| 值 | 行为 |
|---|---|
| **未设 / `null`（默认）** | **中性**：不套语言正则/应答词/长度下限，只保留**结构过滤**（机器文本标记 + compaction 结构位）→ 绝不误杀。 |
| `zh-Hans` | 简体中文档案：一组施压/指责/依赖正则、中文应答词表、`min_chars=6`、中文默认提示词。 |
| `en` | 英文档案（**起步骨架，可扩展**）：常见英文正则、英文应答词表、`min_words≥2`、英文默认提示词。 |
| `auto` | 读宿主 locale：`zh*`→`zh-Hans`，`en*`→`en`；取不到或无档案 → 回退 `en` 并 `WARNING`（仍算「已激活」）。 |
| 其它任意值 | 非法 → `WARNING` + **中性**（fail-safe：不崩、不误过滤）。 |

- **`machine_markers` 恒全局**：`[CONTEXT COMPACTION`、`Gateway message origin (`、`[Cron delivery: ` 等是宿主注入的固定英文包壳，与用户语言无关，**任何模式下都拦**。
- 只有 `proactive_locale` 这一处开关决定「语言过滤是否生效」：不配=不过滤，配了才生效。
- `/proactive-check` 会显示当前 `proactive_locale`（来源 / 是否激活）。

## 如何新增一种语言 profile

1. 在 `proactive/locales/__init__.py` 新增 `LocaleProfile`（参考 `ZH_HANS` / `EN`）：
   - `expression_patterns`：`(area:slug, regex)` 列表，id 用 `area:slug`（如 `pressure:last-chance`），每加一条建议配一条测试；
   - `acknowledgement_words`：整句匹配的纯应答词表；
   - 长度口径：CJK 用 `length_unit="chars"` + `min_chars`；空格分词语言用 `length_unit="words"` + `min_words`；
   - `wording`：一个 `Wording`（软/强制轮的默认文案；工具可用性条款由代码追加，不放进档案）。
2. 把它加入 `PROFILES` 注册表，并在 `_ALIASES` 里补可选别名。
3. 在 `plugin.yaml` 的 `proactive_locale.enum` 里加上该代码。

`en` 明确是**起步骨架**：正则与应答词只覆盖常见形状，欢迎提交扩展（保持 id 形状一致、补测试即可）。
